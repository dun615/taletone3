Read ARCHITECTURE.md first: it maps the flow (data → model → page → script), every folder and every part of the page's script and styles, and where each kind of change goes.

The site is the journey (a phone, a line, the record of every story) at the five chapter routes (`/`, `/about/`, `/approach/`, `/discography/`, `/contact/`, and the same under `/en/` and `/ja/`).

- Never edit generated files (the route pages incl. `en/` and `ja/`, `preview/` (now redirects), `assets/journey/`, `sitemap.xml`); edit the sources (`src/journey/js/`, `src/journey/css/`, `scripts/`) or the `.json` data, then run `npm run build`. Generated files are gitignored: commit sources only; `.github/workflows/deploy.yml` builds, validates and deploys to GitHub Pages on every push to `main` (live commit: `/version.txt`).
- Language lives in the URL: KR at `/`, EN at `/en/`, JP at `/ja/` (content keys stay `kr`/`en`/`jp`).
- Run `npm run check` before committing. CI and the deploy also run the headless-browser check (`.github/scripts/validate-runtime-performance.mjs`, needs `CHROME_PATH` locally): every route in every language on three screens, the whole story scrolled, a record played, an empty inquiry refused.
- Works data has one model: `scripts/works-model.mjs` says which fields a work and a track may have (`WORK_KEYS`, `TRACK_KEYS`), how their media resolve (`mediaOf`) and the rules they keep (`checkWorks`). The page, the site check and the tests all go through it; never read `image`/`thumb`/`audio` of works by hand elsewhere. A new field goes into the model first.
- Before saying a cover, thumbnail or sound is missing, run `npm run audit` (every album track by track, the problems, and the files under assets/works nothing refers to) and search the repository (`git ls-files`, `git log -S`). Never conclude from one field.
- Every work needs a stable lowercase `slug` (used for `?work=` links), its `kind` (`single`, `multilingual`, `album`), an `image` and a small `thumb` (`*-w320.webp`), its `title` (the official one where it was made), its `origin` (`kr`, `en` or `jp`: where it was made) and existing files; an album has no audio of its own, and each of its tracks has its own image, thumb and audio (or video); the title track is `titleTrackIndex`. Its titles in the other languages go in `titles` ({ kr, en, jp } but its own: an official one, or where a language has none, the name it is commonly called by there), never in `translations`; never make up or translate a title, or guess which one a work goes by: ask. `titleIn()` in the works model picks what each language shows. The other work (Sound Engineering, ETC: `mixWorks`, `bgmWorks` in site-content.json) keeps the same `origin` and `titles` (`checkTitledItems`). The featured works are `pinned` 1, 2, 3. Works detail pages are retired: never generate per-work pages again.
- Keep the shape: a part of `src/journey/js/` or `src/journey/css/` does one thing and says so in its first line; new behaviour goes into the part it belongs to (or a new numbered part), not onto the end of the last file. Data shaping stays in `scripts/journey-data.mjs`, HTML in `scripts/journey-page.mjs`.
- The journey's faces are three rounded sans: Manjari (English), NanumSquareRound (Korean) and M PLUS Rounded 1c (declared on the Japanese pages only), in three weights only (thin, regular, bold; `00-base.css`). They are self-hosted subsets in assets/fonts made by `scripts/subset-fonts.py`, which records what each holds in `scripts/font-subsets.json`; `npm test` fails when the site uses a character a subset lacks (run the script again). No serif, handwritten or decorative faces.
- The earlier app (`src/app`, `src/page.html`, `src/styles`, React, `assets/js`) has been removed; news and RSS are retired. The five chapter routes in seo-content.json are the indexable navigation source.
- `npm install` is only needed for the optional tools in `scripts/optimize-assets.mjs` (sharp); build and checks have no dependencies.
